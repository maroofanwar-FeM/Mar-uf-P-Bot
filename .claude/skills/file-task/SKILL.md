# File task

1. **Confirm the scope in your own head before touching anything**: which files/folders, and
   what "done" looks like. If that's genuinely unclear, ask one short question instead of
   guessing (see CLAUDE.md's "Unclear" handling).
2. **Read before you write.** Never overwrite a file you haven't looked at first.
3. **Only touch files inside this project folder** unless the job explicitly names a path
   elsewhere — and if it does, treat any file you didn't create yourself as something to be
   careful with (rule: don't delete or overwrite something you don't own without it being
   flagged as needing Maroof's OK first).
4. **Tidying = organizing, not deleting**, by default. Moving/renaming/consolidating files is
   fine to do directly. Deleting a file that already existed before this job (i.e. one Mar'uf
   didn't just create moments ago) counts as destructive — describe exactly what you want to
   delete and why, and mark the job "needs my OK" instead of deleting it yourself.
5. **Report exactly what changed** — a short list of files created/edited/moved/renamed — so it
   reads clearly on the job card.
6. Hand off to the verifier with that list plus a way to double check it (e.g. "run `ls
   <folder>` and confirm these files exist").
